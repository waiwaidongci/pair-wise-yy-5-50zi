# 手工织锦纹样授权交付台

在原排版台（网格绘制、色线统计、撤销重做、导出 JSON）基础上扩成「送审 — 审核 — 授权交付 — 客户确认」的交付台。直接打开 `index.html` 即可使用，数据存于浏览器 localStorage。

## 业务流程

1. **建档**：填写项目编号、版本号、客户、制版人，保存为方案。方案按「项目编号 + 版本号」唯一，重复不可再建。
2. **送审**：每次送审冻结当时的**网格与色线快照**（尺寸、每格色线、色板颜色、用色统计、指纹、时间），快照只读，之后改动画布不影响已送审内容。
3. **审核**：审核人不能与制版人相同。
   - 驳回必须填写原因，修改后只能用**当前画布的新快照重新送审**；
   - 通过时填写**适用范围**和**授权起止日期**，自动生成交付单（单号 `JS-YYYYMMDD-序号`）。
4. **客户确认**：通过的交付单待客户确认；到期后不可确认。确认后该版本定稿，不能再送审，只能「基于定稿建新版本」。
5. **自动失效**：客户确认前（送审中或待确认期间）只要改动画布或色线（填色、换色线、新建网格、撤销重做等），在途送审单/交付单**自动失效并保留在历史**，附失效原因，须拿新快照重新送审。已确认定稿的交付单永不失效。

## 页面能力

- 底部台账可按**客户**和**状态**（未送审 / 送审中 / 已驳回 / 待确认 / 已到期 / 已确认 / 已失效）筛选，点击行或「载入」打开方案；
- 每版显示交付单号、审核人、适用范围、授权期限与**剩余天数**；右侧面板列出该版全部历史送审单；
- 「导出纹样 JSON」导当前画布；「导出交付单 JSON」导交付信息 + 快照用量 + 流转记录。

## 文件分工（三个业务文件）

| 文件 | 职责 |
| --- | --- |
| `snapshot.js` | 画布快照：网格/色线冻结、用色统计、快照指纹（纯计算，无 DOM） |
| `authorization.js` | 授权判定：方案唯一性、送审/审核回避/驳回、交付单生成、自动失效、到期与剩余天数、筛选（纯逻辑 + localStorage） |
| `app.js` | 页面交互：画布绘制与编辑、所有按钮与表单、台账渲染，串联前两个业务文件 |

`index.html` 只保留页面骨架与样式；三个脚本为普通 `<script>`（无构建、无模块，本地双击即可运行）。
